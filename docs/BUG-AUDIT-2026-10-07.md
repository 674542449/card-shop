# 前端、后台与支付复核（2026-10-07）

本轮基于 `v1.0.8` 和其后文档提交检查，修复位于 `main`；正式版本入口以 GitHub Release 为准。范围包括三个 Blade 模板、React 后台、网页/API 下单、库存、付款创建/回调/对账、退款、权限及运行依赖。

## 修复结果

| 触发场景 | 修复 |
| --- | --- |
| 未交付订单退款处理中或已退，补库存后原回执或人工确认仍能发卡 | 发货事务在订单行锁内检查该笔付款的退款；处理中冻结分配，扣除已退款后不足应付则拒绝。拒绝退款后可交付，另一笔独立有效付款不被误拦截 |
| 商品删除级联清掉停用、锁定或线下已售卡，且仅有商品权限也能删库存 | 分批锁定并核查全部卡密，拒绝保护库存；有未售库存时同时要求卡密写权限。分页末尾保护卡不漏查，空商品仍可按商品权限删除 |
| 库存 Redis 锁释放先 GET 后 DEL，可能删除后来持有者的锁 | Lua 原子比较并删除；数据库行锁继续保护领取，新持有者的锁保留 |
| 卡密页换商品保留旧选择/导入弹窗或迟到响应 | 按商品重新挂载、取消旧请求、清理选择与弹窗，旧响应不进入新页面 |
| 商品编辑较早请求晚返回，打开了旧商品 | 只接受当前加载；新增、关闭和离开页面都取消旧加载 |
| 三模板付款异常页恢复入口不明确，副标题误称订单已结束 | 提供原订单刷新及带订单号的凭据查询；使用服务器状态标题，结果不确定时仍不展示新支付入口 |
| 对账的“网关已付款”提示被当作已发货 | 分别返回收款、交付和人工处理标记，未交付提示明确写出未发货 |
| 未交付的收款已退完，后台仍永久计入付款待核对 | 待办、列表标记、详情和对账提示采用剩余收款判断；全部收款已退回且回执已结清时移出待核对，部分退款和其他未退收款继续保留 |
| 未交付订单已全退仍锁库存和优惠名额 | 全部收款退回后关闭未交付订单，释放预留卡和优惠次数；重复退款完成被拒绝。再次收到新付款保留异常回执，可由有收款权限的管理员核实后恢复交付 |
| USDT JSON 数字签名与 PHP 默认数值字符串不同 | BEpusdt 使用 Go `%v`，传统 EPUSDT 使用固定小数格式；极小 token 数值保存为精确十进制，两种规则独立处理 |
| `source-map-js` 1.2.1 命中高危拒绝服务公告 | 精确覆盖到 1.2.2，更新锁文件、重新构建；npm/Composer 审计未命中当前公告 |
| 核心金额计算使用 BCMath，但 Composer 未声明扩展要求 | 声明 `ext-bcmath`，让源码安装在缺扩展时提前停止；正式镜像本已包含该扩展 |

协议依据：[BEpusdt 签名源码](https://github.com/v03413/BEpusdt/blob/main/app/utils/utils.go)、[传统 EPUSDT 签名源码](https://github.com/assimon/epusdt/blob/v0.0.3/src/util/sign/sign.go)。依赖依据：[GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q)。该依赖用于 Vite/jsdom 构建测试链，本轮没有证明公网商城存在可直接调用该库的入口。

“EPUSDT”选项指传统 API Token + MD5。其仓库当前的新 GMWallet 接口采用 `pid`/`secret_key` 与 HMAC-SHA256，不能按旧接口配置冒充兼容；参见[当前验签实现](https://github.com/assimon/epusdt/blob/master/src/middleware/check_sign.go)。后台选项和部署说明已明确此边界。

## 实际验证

自动化使用隔离库 `cardshop_testing`、Redis 10/11 与外部虚构 keyring，启用真实 PostgreSQL 恢复。新回归涵盖付款退款、库存删除、Redis 所有权和数值签名；三模板在独立 PHP 进程内渲染，后台 DOM 使用真实 React/Ant Design 组件。完整计数见[测试记录](../tests/README.md)。

最终完整 PHP **517 个测试/5021项断言**通过，无错误、失败或跳过；后台 Node **29个**、其他 Node **12个**与Shell **7类**通过。后台重新构建并验证全部产物及源码标记，Composer严格校验和平台要求通过，开发环境就绪和业务健康均正常。

修复前保留了退款/删除保护失败、库存锁误删和数字签名错误；修复后保留正常付款、拒绝退款后交付、独立新付款和合法库存删除等正向对照。首轮锁测试误用未安装的 Mockery，后改为显式代理调用真实 Redis；首轮编辑断言选中了搜索框，后限定抽屉表单。这些脚本错误未记为产品漏洞。

真实 HTTP 的最终复跑使用独立库 `cardshop_security_final_20261007`、Redis 12/13、独立存储、真实 Cookie/CSRF 和回环虚构网关，默认拒绝其他应用 HTTP 出站。**164次请求全部通过**：103次购买/支付回放、28次退款/库存保护、31次后台权限（含21个读取入口）与2次原生Go签名回调；付款及追加场景**79项业务检查通过**。完整结果见[测试记录](../tests/README.md)。前轮证据也保留，未代替最终代码复跑。

覆盖金额与状态伪造、零额/少付、错签名/商户/币种、流水复用、重复下单、跨令牌取卡、优惠有效性、CSRF、越权人工操作及三模板合法取卡。Go 回调验证零额不发卡、大额正确付款只交付一次，并保留极小 USDT 数值。没有真实扣款、退款转账或向外部收件渠道发送测试通知。

原始证据位于忽略目录 `.local/audit-20261007-*`、`.local/security-retry-20261007/` 和 `.local/security-final-20261007/`，不提交运行数据和测试凭据。独立服务结束后停止，保留证据和隔离数据库。

## 限制

本机开发进程原已停止，按项目约定恢复并保留数据和产物。浏览器初次连接失败；恢复服务后，工具因当前错误页的 URL 策略阻止导航，未绕过、未创建或关闭标签。因此本轮界面验证来自 DOM 和服务器渲染/HTTP，**没有浏览器目测或移动端布局验收结论**。

结果只说明已执行场景的观察，真实到账、正式代理和其他攻击组合仍须目标环境验证。已有 `v1.0.8` 的双架构镜像结果不当作本轮修改后的容器验收证据。
