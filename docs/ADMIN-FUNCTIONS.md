适用正式版本：**v1.0.8**。店铺安装见 [首次安装指南](../DEPLOY.md)，对应架构与后台权限设计见 [架构说明](ARCHITECTURE.md)。

核查日期：2026-10-04。范围包括后台页面、对应接口、权限定义、业务服务、数据库约束和任务进程。以下“已实现”表示存在完整处理链路，并有相应回归覆盖；不表示穷尽所有故障、部署环境或攻击组合。

后台入口已找到对应实现，没有发现仅展示菜单、点击后无任何处理的空壳模块。本次发现的主要缺口是已有服务缺少后台恢复入口，以及部分错误和并发场景处理不完整。

## 后台入口调整

- 支付设置统一 EPay、USDT 与自动对账总开关；邮件设置统一发送、测试和模板，自动保存仍只提交已修改字段。
- 任务中心包含通知投递、付款对账和搜索引擎推送；运维包含运行健康、素材和备份。服务端原有权限和任务重试规则保留。旧通知地址保留筛选条件并跳转任务中心。
- 卡密新增 `disabled`（停用）状态；仅未售卡可暂停，停用卡恢复后方可售出。已关联订单、锁定、售后换出卡不能绕过订单流程改库存；线下售出与停用分别操作。
- 首页待办按账户权限展示；退款审核和已批准待打款分别链接，待付款订单不再作为人工待办。

### 卡密操作对照

| 实际场景 | 操作 | 结果 |
| --- | --- | --- |
| 怀疑未售卡失效，需要暂时停止销售 | 暂停销售 | `unsold → disabled`，不再参与下单、换卡或可售库存统计 |
| 已核实停用卡可用 | 恢复销售 | `disabled → unsold`，重新进入可售库存 |
| 已在商城外卖出未售卡 | 登记线下售出 | `unsold → sold`，记录售出时间，不生成商城订单和收入 |
| 误登记线下售出，确认卡密未交付 | 撤销线下售出 | 无订单关联且未换出的 `sold → unsold`，清除售出时间 |
| 订单锁定、已交付或售后换出的卡 | 在订单中按实际情况处理 | 库存页不能强制回库；停用不是撤销交易或退款 |

卡密列表独立统计未售、锁定、已售和停用数量。停用不允许绕过导入查重，删除仍只允许未售卡。所有状态变化由服务端校验并受独立卡密写权限控制。

### 任务中心权限

| 页签 | 查看 | 重试 / 提交 |
| --- | --- | --- |
| 通知投递 | 通知查看权限 | 通知写权限，重试失败或跳过任务 |
| 付款对账任务 | 维护和订单查看权限同时具备 | 维护和订单写权限同时具备，并开启自动对账；只重试失败任务 |
| 搜索引擎推送 | 内容查看权限 | 内容写权限，重试失败任务或提交现有页面 |

任务重试表示重新入队，需对应工作进程执行；对账完成不等于订单已支付，SEO 提交成功不等于收录。运维中的备份为店主专属，不因具有任务查看权限而开放。

## 既有修复

2026-10-07 的 `main` 修复进一步保护商品删除、退款后发货和后台异步编辑；结果见 [复核报告](BUG-AUDIT-2026-10-07.md)。删除空商品只需商品写权限；同时清理未售库存还需卡密写权限。有关联订单、停用、锁定或已售卡密的商品不能删除，可按经营需要下架。

- **订单详情串单风险**：快速切换订单时，旧请求可能覆盖新数据、旧退款或换卡弹窗可能留在新订单上。页面按订单重新挂载并取消旧请求，回归验证迟到响应不会覆盖新订单。
- **设置加载失败仍可编辑**：请求失败时空表单可能继续提交。改为错误页和重新加载入口；测试邮件仅等待已修改字段保存，不回写整份旧表单。
- **对账失败无法在后台恢复**：补齐任务列表和失败重试；单订单成功查询后解除对应失败任务状态，不更改工作进程正在处理的任务，也不把未支付订单标成已支付。
- **旧备份失败记录找不到**：原界面仅显示最近 20 条。改用分页接口并提供未确认失败过滤，旧任务可确认或重试。
- **健康原因和时间标注遗漏**：显示 SEO 心跳、对账队列积压与失败数；自动备份时间明确为北京时间。
- **分类删除竞争**：删除检查与删除同一事务锁定父记录，新增或移动子记录锁定目标分类，数据库外键禁止级联删除商品和文章。
- **同名自动网址并发冲突**：在事务锁内生成并保存 slug，同时提交同名分类不会撞唯一键返回 500；手动重复标识返回校验错误。
- **IPv6 黑名单匹配遗漏**：展开、压缩、大小写和 IPv4 映射写法统一；已有规则规范化但保留原有原因和到期时间。
- **素材归档竞争及按钮误导**：界面按服务器返回的资格显示按钮；文件操作加锁，归档后复查引用，保存引用在事务提交后恢复素材。

## 验证与限制

`v1.0.8` 的 [正式发布流水线](https://github.com/674542449/card-shop/actions/runs/37170509224)已通过原生 AMD64 / ARM64 测试、九服务容器首次安装与重启验收，以及双架构索引发布。每个平台均完成 475 个 PHP 测试 / 4772 项断言、26 个后台 Node 测试、12 个其他 Node 测试。镜像摘要见 [当前版本验收](../tests/README.md#当前正式版验收)；下文的本地验证限制仍然适用。

记录和命令见 [回归检查](../tests/README.md)。2026-10-03 的完整性复核使用隔离 PostgreSQL / Redis、独立 HTTP 服务、回环虚拟支付网关和虚构卡密；未进行真实扣款或对外通知。当时修改本地开发库前完成私有完整备份，应用数据库约束后商品、订单和卡密数量不变。

2026-10-04 的入口调整与卡密停用使用隔离测试库验证，无需数据库结构迁移，不修改本地店铺业务数据。后台界面使用真实 React / Ant Design 组件进行 DOM 回归，本地后台入口和构建资源完成 HTTP 检查。工具能列出现有浏览器标签，但两次连接均超时；按项目防闪退约定没有新建或关闭标签。本轮不声称已完成浏览器目测或移动端布局验收。
